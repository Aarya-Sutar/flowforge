# 1. PROJECT OBJECTIVE

==================================================

FlowForge is an intelligent business request automation platform for organizations.

A company receives different types of requests such as:

- IT support

- HR

- Finance

- Procurement

- Customer service

- Access requests

- General internal business requests

A user submits a request containing:

- title

- description

- requester information

- department

- optional attachment(s)

FlowForge processes the request through an automated pipeline:

User

↓

Next.js Frontend

↓

FastAPI REST API

↓

PostgreSQL

↓

Redis Queue

↓

Celery Worker

↓

AI Classification + Information Extraction

↓

Deterministic Validation / Business Rules

↓

Workflow Routing

↓

Automated Action

↓

Audit Log + Status Tracking

↓

Dashboard

The key architectural idea is:

AI should assist decision-making, but deterministic business logic should control important business actions.

The LLM must NOT be allowed to directly execute arbitrary actions.

# 8. DETERMINISTIC BUSINESS RULE ENGINE

==================================================

This is one of the most important parts of the project.

Do NOT allow the LLM to make the final business decision.

Implement a deterministic rule engine after AI processing.

Example:

IF category == ACCESS_REQUEST

AND confidence >= 0.80

→ route to IT_SECURITY

IF priority == HIGH

→ mark for urgent handling

IF confidence < 0.70

→ route to MANUAL_REVIEW

IF category == FINANCE

AND amount > 100000

→ require manager approval

IF required information is missing

→ move request to NEEDS_INFORMATION

The exact implementation should be maintainable and explainable.

For every request, the system should be able to answer:

- What AI prediction was made?

- What score/metadata was produced?

- Which business rule was evaluated?

- Which rule was triggered?

- Why was the request routed to this team?

- What action was generated?

- When did each processing step happen?

Store triggered-rule information.
